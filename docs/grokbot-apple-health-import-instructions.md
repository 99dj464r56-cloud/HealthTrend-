# Grokbot 执行指示：Apple Health / Fitness 本机导出文件导入

请在现有 Health Trend PDF 项目中实现 Apple「健康」导出数据的**手动、本机导入**。这是静态网页的文件导入功能，不是 HealthKit 原生连接，也不是自动同步。

## 开始前的保护要求

1. 先读取设计规格、README、数据模型、导入流程、图表／PDF、相关测试和隐私文档。
2. 先运行 `git status --short --branch` 并记录现有改动。工作树已有未提交修改属于用户工作：必须保留，不得重置、清理、覆盖或把无关改动纳入提交。
3. 先提交一个小型实施计划和数据映射方案，再开始改动。
4. 只用完全合成的 Apple Health XML/ZIP 测试夹具。不得读取、复制、记录或提交用户真实的健康导出文件、文件名、运动地点、路线、心率、药物、化验结果或截图。
5. 仅执行本文件范围内的本机文件导入，不要创建 GitHub 仓库、发布、联网上传健康数据或实现其他建议项。

## 目标体验

在现有资料工作区添加“导入 Apple 健康数据”入口。用户从 iPhone「健康」导出 XML 后，将文件选入网页；网页在本机解析，先提供可筛选、可核对的预览；用户选择记录类别和日期范围并确认后，才将支持的数据写入本机记录并用于图表／PDF。

Apple 官方说明：iPhone「健康」可以导出健康与健身数据为 XML。导入器可支持原始 XML；如实际导出以 ZIP 封装，也可接受 ZIP，但必须只处理其中明确识别的健康 XML，忽略路线、心电图或其他附件，不能默默导入。

## 数据与交互要求

- 支持至少常见的 `Record` 数值样本、`Workout` 训练记录和 `ActivitySummary` 每日活动摘要；对未知、非数值、格式异常或暂不支持的数据，显示数量和原因，不猜测、不丢失后仍显示“全部导入”。
- 只映射项目确实支持并能正确表达的数据类型，例如步数、活动能量、运动距离、运动时长、心率、体重，以及 workout 类型和时长。具体支持清单应在界面和 README 中列出。
- 保留数据原始类型、原始数值、单位、样本开始／结束时间、来源 App/设备（可用时）、导入文件来源、稳定去重键和导入日期。不得把一整段心率样本错误地合并成单个精确读数；workout 事件与其统计值应保持语义清楚。
- 区分单次样本、每日聚合值和训练事件。除非用户明确选择聚合，否则不要把多条数据求和或平均；任何聚合必须显示聚合方式、周期和原始记录数量。
- 支持用户筛选导入类别和日期区间；导入前显示待导入条数、重复条数、冲突条数、跳过／不支持条数和样本日期范围。
- 对重复数据做幂等识别。完全匹配项标记为重复而默认不再增加；相近但来源或值不同的记录列为冲突，由用户选择，不静默合并。
- 预览应展示有代表性的记录和来源信息。用户确认前不得把候选数据写进 canonical record、图表或 PDF；取消导入不留下半成品。
- 使用正确时区／偏移解析 Apple 日期。保留原时间戳，并避免把本地日历日期因 UTC 转换移动到前一天或后一天。
- 运动与活动应使用独立、清晰的分类；不要把步数、卡路里、时长和心率画在同一数值轴上。单位不兼容的系列分开。PDF 中继续保留用户已确认的重点指标“双重呈现”：重点区和所属类别区都要显示。

## 安全与隐私约束

- 所有解压和 XML 解析均在浏览器本机完成；禁止请求任何远程解析服务或上传 XML/ZIP/记录内容。
- XML 必须使用安全解析器／配置：拒绝 DTD、外部实体和外部资源；防范超大文件、超深节点和 ZIP 解压炸弹。设定并解释压缩文件大小、解压后大小、记录数量上限。
- 不解析或保存 GPS/workout route（位置轨迹）、附件和未被用户选择的数据类型。不得将敏感内容写入 console、日志、错误上报或 URL。
- 原始导出文件及原始 XML 文本默认仅在临时内存中使用，导入结束或取消后释放；只保存用户确认的结构化字段。若实现有任何留存选项，必须默认关闭且由用户明确开启，并提供删除方式；本任务首选不做留存。
- 不请求写入 Apple Health 的权限；本功能只读取用户手动提供的导出文件。不要加入 HealthKit、OAuth、API key、云端 AI 或后台服务。

## 实施与回归测试

- 先检查现有数据模型是否能表达导入类型。若要扩展 schema，加入版本化迁移和回滚测试，保证旧备份／旧记录可读；不要为塞入新数据而把语义不同的 workout 随意伪装成化验观察。
- 测试至少覆盖：合法 XML、ZIP 内 XML、损坏 XML、恶意 DTD／外部实体、超限文件、重复导入、来源不同的冲突、未知类型、单位保留、时区边界、日期筛选、用户取消、确认后保存、取消不保存、旧数据迁移、图表分类及 PDF 输出。
- 测试夹具必须完全虚构，且要覆盖每日汇总和多条单次样本。不得用真实个人导出作夹具或截图。
- 完成后运行项目发布测试：
  `VITE_BASE_PATH=/health-trend-pdf/ npm run test:release`
- 生成一个纯合成的 PDF，逐页渲染检查；同时验证 Network 面板／Playwright 请求记录中没有任何健康字段或文件内容外传。
- 更新 README、隐私说明和测试覆盖清单，明确说明这是“手动 XML 文件导入”，不是实时 HealthKit 同步。
- 最后汇报：变更文件、支持的数据类型、跳过类型、迁移策略、测试结果、PDF 视觉检查结果及所有限制。不要宣称能读取用户的全部 Apple Health 历史，因为授权和导出内容可能不完整。
